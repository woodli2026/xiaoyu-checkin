## 1. 快速开始（开发者工具打开）

1. 打开 **微信开发者工具** → 导入项目 → 目录选择本仓库根目录 `D:\MyWorkspace\xiaoyu-checkin`。
2. `project.config.json` 的 `appid` 已是 `wxb80f4e43f9c99714`。**若这不是你的 AppID**：改成本人的（或临时改成 `touristappid` 走游客模式，但游客模式下**无法真机预览、无法使用云开发**）。
3. 编译运行。此时 `miniprogram/config.js` 的 `CLOUD_ENV` 为空 → **自动走本地兜底**，无需任何后端配置即可完整体验。
4. 首次进入会有隐私协议弹窗 → 同意 → 进入首页（展示模式）。
5. 新建账号**开箱自带 3 个任务 + 2 个奖励**（见 §2.1），设一次 PIN 即可直接走「打卡 → 攒星星 → 兑换」全链路。

> 本地兜底模式下数据存在手机本地存储（`wx.storage`）。「我」页有「重置本地演示数据」按钮，方便反复演示。
> 「我」页「编辑孩子档案」可把默认的「宝宝 / 🧒」改成「小雨 / 👧」。

### 1.1 本地兜底模式能验证什么（无需后端）
账号自动创建、设置/校验 PIN、双模式切换、任务/奖励开箱预置与增删改、打卡（防重复、星星累加、连续天数）、日历点亮、兑换（库存/星星扣减/限次与不限次）、软删、孩子档案昵称头像编辑、多孩子切换。业务逻辑已用 `node:test` 全量覆盖（见 §6）。

## 3. 切到云端（真库）

### 3.1 前端三处改动
1. `project.config.json` → `"appid": "你的AppID"`。
2. `miniprogram/config.js` → `CLOUD_ENV: '你的云环境ID'`（云开发控制台首页可查）。
3. 无需改其它代码；`app.js` 会自动 `wx.cloud.init` 并把数据层切到云端。

### 3.2 云开发初始化
1. 开发者工具 → 云开发 → 开通（选按量付费/免费额度）。
2. 建 7 个集合：`users` `children` `tasks` `rewards` `checkIns` `redemptions` `pointsLog`。
3. 集合权限：建议都设为 **「仅创建者可读写」**（写逻辑仍走云函数，权限更严可选「仅管理端可写」）。
4. 建索引（重要）：
   - `users.openid` 唯一索引（防并发首登重复建号）。
   - `checkIns` 复合唯一索引 `ownerId + childId + taskId + date`（防同日重复打卡的硬保障）。
   - `tasks`/`rewards` 建议 `childId + deleted` 普通索引。

### 3.3 上传云函数
在开发者工具左侧「cloudfunctions」目录，对 **每个函数**右键 →「上传并部署：云端安装依赖」。共 11 个：
`login` `unlockParent` `getDashboard` `checkIn` `redeem` `taskCRUD` `rewardCRUD` `childSwitch` `childCRUD` `setPin` `resetPin`。

> 每个函数目录已自带一份 `lib/`（由 `cloudfunctions/setup.js` 同步），因此可直接上传。若你改动了 `cloudfunctions/lib/`，请执行 `npm run sync`（= `node cloudfunctions/setup.js`）重新同步后再上传。

### 3.4 云函数环境变量（切云端时填）
在云开发控制台 → 每个云函数 → 配置 → 环境变量，为**所有**云函数加上这两项（值必须全函数一致，否则令牌/PIN 校验互相不认）：

```ini
XY_TOKEN_SECRET=37ff329377aa52a16408c9e3b17b4d4e98a9e69f7b18313eb6c0fb9d93274523
XY_PIN_SALT=46a84d0ef7ad40a58b41e78775b93b9935d93a05620e341336b74e833db56660
```

> 上面两串是 2026-09-17 用密码学随机源生成的 32 字节（64 hex）密钥，已可直接使用；**不设置则回退到代码内置的开发密钥**（`xiaoyu-dev-secret-change-me` / `xiaoyu-pin-salt`），仅能用于本地内测。
> ⚠️ 若要换新值：重新生成后必须同时更新所有云函数的环境变量。**本仓库若推送到公开平台，请先移除本节密钥**（`.gitignore` 未覆盖 README）。

## 8. 与「详细计划 / PRD」的偏差说明（重要）

| # | 计划原案 | 实际实现 | 原因 |
|---|---|---|---|
| 1 | 家长令牌用「服务端 Map 作 store」 | 改为 **无状态 HMAC 签名令牌**（`lib/token.js`） | 云开发 8 个云函数各自独立实例、内存不共享，Map 方案在 `checkIn` 读不到 `unlockParent` 写入的值，不可行。签名令牌任意函数可独立校验，仍满足「必须持有效 token 才能写」。 |
| 2 | 8 个云函数 | **11 个**（增补 `setPin`、`resetPin`、`childCRUD`） | T17「PIN 设置/重置」需要服务端接口，§3 清单遗漏；「编辑孩子档案」为新增能力（见 #6）。 |
| 3 | `jest` 单测 | **`node:test`（零依赖）** | 免去 npm 安装，离线可跑；用例等价。 |
| 4 | `getDashboard` 返回面 | 增补 `children`、`checkIns`（紧凑）| 「我」页多孩子选择器与任意日期日明细需要，避免额外接口。 |
| 5 | 同步 lib 到各函数 | 提供 `cloudfunctions/setup.js` | 开发者工具上传仅打包函数目录，跨目录 require 不会上传，故各函数自带 `lib/`。 |
| 6 | PRD-MINE-01 无「编辑孩子档案」 | **新增** `childCRUD` + 「我」页编辑面板（昵称 ≤12 字 + 64 格头像选择） | 本轮确认新增：默认档案名「宝宝」无法改成产品命名来源「小雨」，不便于演示与真实使用。属 MVP 之外的新增能力。 |
| 7 | 新账号任务/奖励为空列表 | **预置 3 任务 + 2 奖励**（`lib/seed.js`） | 本轮确认：空列表需先手工建数据才能验收，改为开箱可用，做到「导入即验收」。云端与本地兜底行为一致。 |

- 卡片/日历等视觉按锁定原型实现（糖果配色、圆角、动效）；如需完全还原字体，可把字体文件放入并加 `@font-face`（注意主包 2MB 上限，建议用子包或远程字体方案）。
- 「编辑孩子档案」与「预置开箱数据」为 PRD 之外的新增项（§8 #6/#7），已记入偏差表。

### 11.4 PIN 位数的最终口径（一次全局不一致的收口）
- **最终口径：6 位，默认 `123456`。**
- **事情经过**：最初反馈「默认pin密码为12345678」，按 8 位实现；随后 `cloudfunctions/lib/pin.js`（真源）被改成 6 位（`DEFAULT_PIN='123456'`、`PIN_LENGTH=6`），但**其余 11 处仍是 8 位** —— 11 个云函数副本、前端 PIN 键盘（8 圆点）、本地兜底层、README、单测。
- **这处不一致的实际危害**：只要跑一次 `npm run sync`，真源的 6 位就会被推给全部云函数，届时**云端要求 6 位、前端键盘发 8 位，PIN 永远输不对**。这类「配置漂移」不会报错，只会静默失败。
- **处置**：经确认统一按 **6 位**收口，共改 6 处：`lib/pin.js` 注释、`setPin` 错误文案、`pin-pad.js`（`PIN_LENGTH` + 6 圆点）、`pin-pad.wxml` 文案、`pin-pad.wxss` 圆点间距、`local.js` 常量、`mine.js` / `mine.wxml` 文案、两份单测；并重跑 `npm run sync` 让 11 个副本一致。
- **防护**：`__tests__/local.test.js` 的「默认 PIN 口径：本地兜底与云端 lib 必须一致」用例会守住两端，任何一侧漂移都会让 `npm test` 变红。

### 11.6 「默认 PIN 123456」的**存量账号迁移**（关键，不改这里等于没改）
只把代码改成 6 位是**不够的**。原因：
1. 账号一旦建过号，`users.pinSet` 就为 `true`；旧的迁移逻辑是 `if (!user.pinSet)` → **对这种账号完全不动作**。
2. 它的 `pinHash` 里存的是 8 位口径的 `hash('12345678')`，**永远匹配不上 6 位输入**。
3. 表现为：输 `123456` 一直提示「PIN 不正确」，**而且不报错、不崩溃**，看起来像"密码被改了"。

处置：引入 **PIN 方案版本标记 `PIN_SCHEME = 'len6-v1'`**（定义在 `lib/pin.js`，`local.js` 有一份镜像）：
- `users.pinScheme` 与当前方案不一致的历史账号（含"压根没这个字段"的），会在 **`login` 时自动重置为默认 PIN 并打上新标记**；
- 新建号、`setPin`、`resetPin` 三条路径都会写入该标记；
- **迁移只对旧账号触发一次**：用户改成自定义 PIN 后 `pinScheme` 已是当前值，再次登录不会被重置回默认（有单测守住）；
- 云端 `cloudfunctions/login` 与本地兜底 `services/local.js` 的 `login` 两套都已同步。
- 今后若再改 PIN 位数/哈希口径，**必须同步递增 `PIN_SCHEME`**，否则又会出现同类"进不去"的死状态。

> **如果你想立刻进家长模式**（不想等重启触发迁移）：点「我」页的**「忘记 PIN？重置」**——它会把 PIN 直接恢复成 `123456`，且该操作**不需要 token**，随时可用。

### 11.7 PIN 面板「输了没反应」——上一轮修复引入的缺陷
- **症状**：PIN 输入满位数会自动提交；一旦失败，**第二次再输就完全没反应**（键盘像坏了），用户描述为「PIN 录入后还是进不去」。
- **根因**：上一轮为修「验证失败后无法重输」，给组件加了 `error` observer —— `if (err) 清空 input`。但**同一句错误文案第二次不会发生变化** → observer 不再触发 → 输入停在满位数 → 被 `input.length >= PIN_LENGTH` 拦掉。
- **修复**：改用**递增计数 `attempt`**。父层每处理完一次提交（无论成败）就 `attempt + 1`，组件 observer 见变化即清空输入 —— 与错误文案是否变化无关，可靠。
  - `home.js` / `mine.js` 的 `onPinComplete` 失败、`doSetPin` 失败、`onPinForgot` 三条路径都会递增。
- **教训**：用「值是否变化」驱动副作用（observer / watch）时，**等值重复赋值不会触发**。凡是"每次事件都必须执行"的逻辑，要用递增令牌/序号，而不是把状态压成布尔或字符串。

### 11.8 PIN 面板补齐自救入口（设计稿本来就有）
- 设计稿的 PIN 遮罩底部有「忘记 PIN？用微信验证重置」，**首版漏掉了**。
- 现已补齐：`pin-pad` 新增 `forgotText` 属性与 `forgot` 事件，PIN 面板底部常驻**「忘记 PIN？恢复默认」**；点击即调 `resetPin`（**不需要家长模式**）把 PIN 恢复为 `123456` 并提示重输。首页锁图标与「我」页两个入口都已接入；设置/确认 PIN 的场景不显示该入口（不传 `forgotText` 即隐藏）。
- 同时 `unlockParent`（云函数 + 本地兜底）新增错误码 **`PIN_SCHEME_STALE`**：账号的 PIN 方案与当前不一致时，直接提示「PIN 规则已更新，请点下方『忘记 PIN』恢复默认后重试」，而不是含糊的「PIN 不正确」——**让用户知道下一步该做什么**。

### 11.10 打卡弹层内容空白 —— `scroll-view` 的高度陷阱
- **症状**：点日历日期后，弹层只显示标题「9月17日」和一个 ×，**下面完全空白**；连空态文案「这天没有需要打卡的任务」都不出现。而看板此时显示 `0/1 今日完成` —— 说明**任务数据是有的**，问题在渲染。
- **根因**：弹层内容用 `<scroll-view>` 包裹，CSS 只给了 `.ds-body { max-height: 62vh; }`。
  **小程序 `<scroll-view>` 必须有确定的 `height`**（或处在有确定高度的 flex 容器中）。只给 `max-height` 时它算不出高度 → **内容区高度归零**，所有子元素（含空态文案）被整体吞掉。
  这正是"标题在、内容全无"的原因 —— 如果单纯是数据为空，空态文案本该显示出来。
- **修复**：放弃 `scroll-view`，改为普通 `view`，滚动交给面板自身：`.ds-panel { max-height: 82vh; overflow-y: auto; }`。内容少时贴合、多时封顶。
- **同类一并修**：图标选择器 `emoji-picker` 是同一写法，同步改为面板自身滚动。**现已全项目无 `scroll-view` 实际用法**（脚本核验）。
- **顺带加固**：空态判断由 `todo.length === 0` 改为 `!todo.length`，属性未传入（undefined）时也能正确显示空态。
- **教训**：这是本项目第 3 个「只有跑起来才暴露」的组件级坑（前两个是 `<input>` 自带高度、自定义 tabBar 的层级）。共同点是 —— **小程序原生组件有隐式的布局前提，不能按普通 HTML 元素的直觉写 CSS**。遇到"元素在但看不见"，先怀疑**高度 / 层级**，而不是数据。

### 11.11 修正：页面内的 z-index **压不住**自定义 tabBar（§11.5 的结论被证伪）
- **证伪过程**：按 §11.5 把弹层 `z-index` 提到 300、自定义 tabBar 降到 90 之后，实测弹层底部**仍被 tabBar 盖住**（诊断文字被压住，用户截图可见）。
- **正确结论**：**自定义 tabBar 不参与页面的 z-index 层叠竞争**。它是独立组件节点、渲染在页面内容之上，页面内任何 `z-index` 都无法越过它。
- **最终方案：打开全屏弹层时主动隐藏 tabBar**
  - 新增 `miniprogram/utils/tabbar.js`：`setTabBarHidden(page, hidden)`，内部走 `page.getTabBar().setData({ hidden })`；
  - `custom-tab-bar` 增加 `hidden` 状态，为真时 `display: none`；
  - 三个页面共 **31 处**调用：打开弹层 → `true`，关闭 → `false`；各页 `onShow` 再重置一次，防止残留；
  - **一个关键细节**：从编辑弹层里再打开「图标选择器」时，关闭图标选择器**不能恢复** tabBar（因为编辑弹层还开着）。因此 `tasks` 的 `onIconPick/onIconClose`、`mine` 的 `onEditAvatarClose/onEditAvatarPick` 都不恢复；`cancelDelete` 用 `!!this.data.showEditor` 条件判断。
- **保留但降级**：弹层**之间**的相对层级仍用 z-index（`mask 200 ＜ day-sheet 300 ＜ emoji-picker 400 ＜ pin-pad 500`），但**不要用它去压 tabBar**。
- **教训**：「层级不够就加 z-index」是一个**需要验证的假设，不是常识**。自定义 tabBar、原生导航栏、`video`/`map` 等原生组件往往不在同一个层叠上下文里，z-index 对它们无效。遇到压不住，先确认**这个元素参不参与 z-index 竞争**，而不是继续加数字。

### 11.12 第四轮反馈（弹层无法取消 / 点蒙层不关闭）

| # | 反馈 | 状态 |
|---|---|---|
| 1 | 新增/编辑任务、奖励弹层右上角**没有关闭按钮**，无法取消新增 | 已修：新增通用类 `.sheet-x`（右上角圆形 ×） |
| 2 | 所有弹层应支持**点击弹层外的空白处关闭** | 已修：9 处蒙层全部按统一约定接入 |

**根因：`catchtap` 只阻止穿透，不响应点击**

- `tasks` / `home` 的弹层 `.mask` 上**什么都没绑** → 点蒙层毫无反应；
- 三个组件（`day-sheet` / `emoji-picker` / `pin-pad`）的蒙层上写的是 `catchtap="noop"` —— 本意是「阻止点击穿透到页面」，但它**把蒙层自身的点击也一并吞掉了** → 同样点哪儿都不关；
- 只有 `mine` 页的三个弹层写法本来就是对的，本轮把它确立为**全局统一约定**并写进 `app.wxss` 注释：

```
.mask  上绑 bindtap="关闭方法"      ← 点这里 = 关闭
.sheet 上绑 catchtap="noop"        ← 点内容不关闭（冒泡在此被吞掉）
```

> ⚠️ **绝不要在 `.mask` 上写 `catchtap`** —— 那会导致「点哪儿都关不掉」。
> 组件内部的等价写法：蒙层用 `catchtap="onMask"`（catch 是为了不穿透到页面，同时触发自己的关闭），面板用 `catchtap="noop"`。

### 11.13 第五轮反馈：保存任务后底部导航消失（tabBar 显隐改为「派生」）

**反馈**：新增/编辑任务并保存后，最下面的导航整块消失。

**直接原因**：`tasks.save()` 保存成功后写的是

```js
this.setData({ showEditor: false });   // ← 只关了弹层，没有恢复 tabBar
```

而 `setTabBarHidden(this, false)` 只写在 `closeEditor()` 里 —— `save` 走的是自己那条路径，于是 `hidden: true` 残留，底部导航整块消失。

**但真正的病因是机制**：「tabBar 显隐」原本靠 **31 处人工配对**（每处打开弹层写 `true`、关闭写 `false`）。这种约定在 N 大了以后**必然有漏** —— 这已经是同类问题的第二次（第一次是内层弹层关闭时误恢复，靠 `!!this.data.showEditor` 特判绕过的）。

**根治：把「显隐」从「人工配对」改成「由弹层状态派生」**

`utils/tabbar.js` 现在提供：

| 导出 | 作用 |
|---|---|
| `SHEET_KEYS` | 全部全屏弹层的开关字段清单（**新增弹层必须登记**，测试会校验） |
| `syncTabBar(page)` | 按 `page.data` 里的弹层开关，算出 tabBar 应否隐藏 |
| `attachTabBarSync(page)` | 包装 `page.setData`，**每次 setData 之后自动同步一次** |

三个页面只需在 `onShow` 里调用一次 `attachTabBarSync(this)`，其余地方**什么都不用管**。

- 顺手优化：`setTabBarHidden` 增加「值未变化则跳过」，避免每次 setData 都白刷一次组件渲染。
- **副产品**：原先要特判的场景**自动正确**了 —— 从编辑弹层里打开图标选择器、再关掉它时 `showEditor` 仍为 true → tabBar 保持隐藏，不再需要任何条件判断。
- 页面里仍留有约 20 处旧的显式调用，属**冗余兜底**（方向与派生结果一致，不会冲突）；`tabbar.js` 注释已注明：新增代码不要再写它们。

**回归守卫**：新增 `__tests__/tabbar.test.js`（8 条）。其中一条直接复现本次事故路径：

```
openCreateTask → setData({showEditor:true})   ⇒ 应隐藏
save           → setData({showEditor:false})  ⇒ 必须恢复显示   ← 本次 bug 的守卫
```

另含「内层弹层关闭不得误恢复」「多弹层并存需全部关闭才恢复」「SHEET_KEYS 覆盖校验」「无状态变化时不触发组件渲染」。

**顺带清理**：`mine.js` 的 `showChild` 为废弃字段（多孩子已改为横排直接点击切换，wxml 无引用），已删除。

**值得记住的一点**：这轮修的不只是一个漏掉的调用，而是**把「必须记得配对」的机制换成了「不可能漏」的机制**。凡是「A 变化时必须同步做 B」这类约定，只要靠人在 N 处维护，N 一大必然漏；**从 A 派生 B** 才是一劳永逸。

### 11.14 第六轮反馈：星星改为手动录入 + 标签简化

| # | 反馈 | 处理 |
|---|---|---|
| 1 | 任务新增/编辑：「星星分值」标签改为「**星星**」 | 已改 |
| 2 | 任务的星星控件由步进器改为**文本编辑控件**（直接手输数字） | 已改（§11.9 第 1 项的步进器方案被本轮推翻） |
| 3 | 奖励新增/编辑：「星星 cost」标签改为「**星星**」 | 已改 |

**改动**
- `tasks.wxml`：两处统一为 `<text class="lab">星星</text>` + `<input class="inp num" type="number" bindinput="onNumInput" />`。
- `tasks.js`：`onStep`（步进器）→ `onNumInput`（手动录入）；校验提示由「星星至少为 1」改为 **「请填写 1–99 的星星数」**（补上上界校验）。
- `app.wxss`：删除 `.stepper` / `.st-btn` / `.st-val`；新增 `.inp.num`（220rpx 窄框、居中、`color: var(--star)` + 加粗，让数字更醒目）。

**一个必须注意的实现细节：录入过程中不能立即 clamp 到最小值**

如果写成在 `onNumInput` 里 `Math.max(1, ...)`，用户删掉原值时输入框会**立刻跳回 1** → 删不干净、无法重新输入（与 §11.7 的 PIN 面板是同一类"输入态被过早规范化"的问题）。

因此改为：**只过滤非数字字符、允许暂时为空**，取值范围留到**保存时校验**：

```js
onNumInput(e) {
  const field = e.currentTarget.dataset.field;
  let v = String(e.detail.value == null ? '' : e.detail.value).replace(/\D/g, '');
  if (v.length > 2) v = v.slice(0, 2);   // 最多两位 → 有效范围 1–99
  this.setData({ ['form.' + field]: v });
}
```

> 通用原则：**输入框的"中间态"必须允许非法值**（空、半截），只在提交时做规范化与校验。否则用户每敲一个字符就被框架改写一次，表现为"打不进去"。

**取舍说明**：用 2 位截断与保存校验（≤99）保持一致；不额外加 `maxlength`，避免"第 3 位打不进去"与"被静默截断"两种行为叠加造成困惑。
